# Escala de Serviço por Folga (Duty Roster by Rest)

[Português](README.md) | English

A small local web app for building a daily duty roster. It runs on Python,
stores data in the browser, and exports an Excel file. It is designed for one
person per day and keeps the military rank hierarchy used by the original
project.

## Quick start

### 1. Check Python

On Linux or macOS, copy and paste:

```
python3 --version
```

On Windows, copy and paste:

```
python --version
```

If you see `Python 3.10` or newer, go to step 2. Otherwise, install Python 3.10+
from https://www.python.org/downloads/. On Windows, check **Add Python to PATH**.

### 2. Clone the repository

Replace `YOUR_USERNAME` with your GitHub username:

```
git clone https://github.com/YOUR_USERNAME/escala-de-servico-por-folga.git
cd escala-de-servico-por-folga
```

### 3. Create a virtual environment and install

```
python3 -m venv .venv
```

Activate it.

Linux or macOS:

```
source .venv/bin/activate
```

Windows:

```
.venv\Scripts\activate
```

Install the dependency:

```
pip install -r requirements.txt
```

### 4. Run

Linux or macOS:

```
python3 app.py
```

Windows:

```
python app.py
```

### 5. Open

```
http://127.0.0.1:8770/
```

If the browser does not open by itself, use the address above. To stop, press
Ctrl+C in the terminal.

## What it does

- Two independent series: weekday (PRETA) and weekend/holiday (VERMELHA).
- Each day, picks the eligible person with the most days off in that series.
- Handles unavailable periods, "do not schedule" days, return days and new
  people with a guaranteed first duty.
- Tie-break by lower rank (more junior), then the Desempate field, then name.
- Inherits the last counter of each series from the previous month.
- If nobody is eligible, relaxes the rule and records a warning.
- Stores the roster in the browser. No database.
- Exports an Excel file with Entrada, Diário and Grade tabs.

The default roster has five fictional people: ALFA, BRAVO, CHARLIE, DELTA and
ECHO. Replace them with your own roster in block 3.

## Main screens

1. **Configuration**: month, holidays, recess, previous-month file and state
   backup.
2. **Who competes**: unavailable periods and "do not schedule" days.
3. **Roster**: name, rank, branch, specialty, fixed days off, tie-break and
   observations.

Buttons at the top: **Preview**, **Generate .xlsx** and **Reset**.

## Data and backup

The state is stored in the browser's `localStorage`. It is not shared between
browsers or computers. Use **Export state** and **Import state** to back up or
move the state as JSON.

## Previous month

The **Load days off** button expects a spreadsheet generated by this app
(`Entrada` and `Grade` tabs) or the old model (`Escala` tab). An arbitrary
spreadsheet is not imported.

## Customization

The full guide is in the Portuguese README. Main points:

- More than one person per day: `computar`, `visao`, `render_diario`,
  `render_grade`.
- Change the "most rested" rule: the `min(...)` key in `computar`.
- Change titles or organization: `index.html`, `cfg`, `render_*`.
- Change ranks: `POSTOS`, `parse_posto`, `ROT_EB_FA`, `ROT_MB`.

Run the tests after any change:

```
python3 teste.py
python3 teste_servidor.py
```

## Docker

Docker is optional. systemd is the recommended mode on Linux, and you do not
need Docker Compose: this is a single container.

First clone the repository and enter the folder (step 2 of Quick start). You do
not need Python for the Docker path. The repository includes a `Dockerfile`.
Build the image from inside the project folder:

```
docker build -t escala-de-servico-por-folga .
```

The dot is the build context, the current folder. It is not a typo. Then run:

```
docker run --rm -p 127.0.0.1:8770:8770 escala-de-servico-por-folga
```

Open:

```
http://127.0.0.1:8770/
```

The `PERMITIR` list inside the container needs the Docker bridge gateway
(`172.17.0.1` by default) or `--network host` on Linux. See the Portuguese
README, section 14, for details.

## Security

The app has no login. Access control is the `PERMITIR` IP list. Run it on a
local network or behind an authenticated proxy. Do not expose it directly to
the internet. Data stays in the browser. See [SECURITY.md](SECURITY.md).
